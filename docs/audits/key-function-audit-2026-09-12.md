# 0.4.0 关键功能审计

范围：新包管理器页面及清单查询，以及环境扫描、下载、安装、切换卸载、PATH、配置、缓存、迁移重装的关键调用链。本审计不是对所有第三方包和外部程序的兼容性保证。

## 功能及设计

包管理器功能从 Paths 移至 PackageManagers，原状态和操作只保留一份。包列表由 InstalledPackages 展示；Rust packages 模块负责结构化列表解析，复用 pkgtools 的实例定位和命令执行、global_reinstall 的 pnpm 布局识别。环境扫描与缓存统计共用 fsutil 目录统计，避免两套“完整性”判断继续分叉。

写命令只要求成功退出；文本查询要求有效标准输出；JSON 查询使用 serde_json 并独立处理“部分结果+非零退出码”。这三种业务不能复用“必须非空”这一判断。包列表可读但不能安装的来源不等于读取失败。

## 当前限制

- 新列表针对路径管理支持的 npm/pnpm/Yarn Classic/pip；不自动扩展成 Cargo、Maven、Gradle 的统一包卸载器。Node 项目显示直接依赖，pip 显示当前解释器的分发包。
- Yarn Berry/PnP、私有索引认证设置、跨应用重启续装和原依赖树完整重建尚不支持；这些场景明确显示限制。
- 包清单当前按名排序并支持搜索，未增加更新或卸载按钮，避免把只读查看混成未经验证的修改流程。
- 来源页面随供应商网站变动；下载尚无统一的供应商校验和/签名校验。已有 HTTPS/解压校验不等同于供应商身份签名。
- 外部安装器、并发外部文件写入、跨磁盘权限及第三方脚本副作用无法由现有测试覆盖全部组合。当前程序的互斥锁不跨多个 EnvCon 进程。
- 网络中断、巨量目录性能和所有真实包运行时兼容性仍需在实际场景验证。本轮没有声称所有未来错误已被消除。

验证结果与构建产物记录在 progress.md。
