# 包管理器（0.5.2）

左侧新增独立的“包管理器”入口。“路径管理”保留 PATH 和开发环境变量。

顶部十种管理器使用与环境类型相同的选择按钮。绿灯表示已检测并验证可运行，灰灯表示未检测到；检测中、读取失败或已发现但无法运行时显示黄灯，悬停可查看具体状态。当前选中的可执行文件会显示版本和路径。右上角刷新重新检测可用性。

“更新当前工具”只表示按原安装方式尝试更新包管理器自身，不是升级全部全局包，也不查询官方最新版本作为成功依据。npm、pnpm、Yarn Classic、pip、Bun、uv 和 Composer 有条件支持自更新；pipx、Cargo、.NET CLI 没有通用自更新命令。更新后会重新读取原命令版本：版本变化、命令成功但版本未变化、无法解析版本分别提示，后两者都不能证明已经是最新版。Yarn Berry 需要在项目中使用 `yarn set version`。

所选管理器在“已安装包”和“路径与迁移”之间保持一致。路径视图只显示所选管理器的配置和迁移/重装操作，“一键配置全部”仍作用于全部可用管理器，开发缓存仍集中展示。

## 已安装包

选择管理器和范围，列表显示包名、已安装版本、安装位置和诊断，可按名称、版本或路径搜索，并打开安装位置。

| 管理器 | 当前范围 | 指定目录 |
| --- | --- | --- |
| npm | 当前实例的全局包 | Node 项目的直接依赖，含开发及可选依赖 |
| pnpm | 传统全局目录及 v11 活动安装组 | 项目的直接依赖 |
| Yarn Classic | 全局 package.json 中声明的包 | 项目的直接依赖 |
| pip | 当前 Python 可见的已安装分发包 | Windows venv 根目录，须含 Scripts/python.exe |
| Bun | 独立全局目录的顶层包 | 项目的直接依赖，含开发及可选依赖 |
| uv Tools | uv 工具目录与 receipt | 历史工具目录 |
| pipx | venv 主包及安装元数据 | 历史 PIPX_HOME |
| Cargo | .crates.toml 中的安装记录 | 历史 install root |
| Composer | require/require-dev 顶层包及已装版本 | Composer 项目 |
| .NET Tools | .store 工具安装记录 | 历史 tool-path |

- 项目目录需要显式点击刷新；切换管理器或范围不会继续显示旧查询结果。
- 所有管理器均有独立历史目录范围，直接读取安装元数据，支持选择受管及常见目录、手动输入目录、搜索并进入重装。pip 对应历史 site-packages。此查询不需要旧启动器可运行。
- 修改全局配置后，原位置的包不会出现在“全局包”中；需在历史范围选择旧目录。npm 隐藏更新残留被跳过，正常包的损坏元数据仍有诊断。
- 未安装、损坏依赖会显示原因。查询失败不会被当成空包清单。
- npm/pnpm JSON 查询能保留依赖异常时返回的部分结果，并显示警告。
- pnpm 全局清单直接读取目录元数据，避免 list --global 对 bin 目录的写权限检查。此列表包括顶层包，不是所有传递依赖。
- pip 优先使用 inspect；旧版 pip 回退 list，路径不可得时显示未知。inspect 返回的路径为分发包元数据位置。
- Yarn Berry/PnP 清单不支持，会明确显示错误；不会静默使用另一个管理器替代。

## 路径与迁移

集中放置十种管理器的路径设置、数据迁移、重装旧包及开发缓存清理。操作由统一能力清单控制：

- “仅设置路径”修改配置，不移动已有文件。批量配置分别报告成功与失败；部分配置失败时返回已完成步骤。
- pnpm 的缓存/存储项读取 store path，写入 store-dir。管理器可能在配置路径下增加版本子目录，这是正常布局。
- “迁移数据”复制、校验、备份并创建旧路径兼容链接。
- “重装旧包”在新目录或已配置的空普通目录安装固定版本，默认目标取当前全局配置。pnpm/Yarn 不额外添加 global 层；预览显示实际全局、命令和缓存/存储路径。非空或链接目标会被拒绝。完成后需验证命令以及命令目录的 PATH 配置。
- 0.4.2 起，重装全部成功后可预览并确认卸载指定旧包；不自动删除，详情见 [旧包清理](old-package-cleanup.md)。
- “开发缓存”包含 npm、pnpm、Yarn、pip 及构建工具缓存。执行前再次核对显示路径，拒绝管理根、用户根、运行时和明显的项目目录；部分清理失败不会显示为全部成功。

详见 [目录迁移](package-manager-migration.md)、[全局包重装](global-package-reinstall.md)、[Python 包重装](python-package-reinstall.md) 和 [关键功能审计](../audits/key-function-audit-2026-09-12.md)。

## 能力边界

| 管理器 | 全局目录配置 | 缓存配置 | 全局数据迁移 | 固定版本恢复 |
| --- | --- | --- | --- | --- |
| npm / pnpm / Yarn Classic / Bun | 支持 | 支持 | 支持 | 独立全局目录 |
| pip | 不适用 | 支持 | 不支持 | 新 venv |
| uv Tools / pipx | 支持，含命令目录 | 支持 | 支持 | 独立工具目录 |
| Cargo | CARGO_INSTALL_ROOT | 不提供 | 支持，拒绝包含运行时的根 | 独立安装根 |
| Composer | COMPOSER_HOME | 支持 | 支持 | 独立 Composer home |
| .NET Tools | 默认全局目录不可永久改写 | NuGet 包缓存 | 支持 | 显式 tool-path |

每种恢复流程均接入成功后的可选旧包清理；来源、版本、安装文件范围不确定时保留旧包并显示原因。pipx 注入包、额外安装参数，uv 附加要求/自定义选项，以及 Git、本地和未知私有仓库来源不自动替换为公共仓库包。

Cargo 的 CARGO_HOME 含配置、凭证和安装记录，因此不作为可随意改写的缓存目录。uv/pipx 的 Python 包恢复仍受原解释器兼容性约束，不会自动下载 Python。WinGet、Scoop、Chocolatey 和 Conda 尚未接入此工作区。

## 旧包扫描

0.5.1 可在扫描来源中直接预览并删除旧包，无需先重装；默认不选择任何包，执行前再次验证来源。npm 缺少来源记录时，可明确确认从 `registry.npmjs.org` 下载同名固定版本；这不恢复原始来源，不适用于私有包。工具自更新及后台扫描的具体支持范围见 [0.5.1 审计](../audits/key-function-audit-2026-09-15.md)。

“旧包扫描”提供常见位置、全部本地固定/可移动磁盘、指定目录三种范围，可停止并保留结果。按管理器及目录分组，显示安装记录数量和可重装数量；展开可查看版本与阻止恢复的原因，直接进入对应重装窗口。

扫描不执行包目录中的程序。排除可识别的项目 Node 依赖、缓存和依赖树，不递归跟随目录链接；达到 25 万目录、5 分钟或 64 层深度上限时显示不完整结果。权限错误、链接跳过和根目录清单保留在扫描记录中。全部本地磁盘不等于保证找到每个包，网络路径可显式选择。

“当前配置”仅表示与已读取的全局配置相符；其他目录和 Python 环境显示“其他来源，待核对”，不推断它们已经废弃。旧包清单可读不代表有足够来源信息进行自动重装。

0.5.0 已覆盖 Rust 元数据/目录边界夹具、十管理器界面能力、扫描取消和来源到恢复流程联动。真实隔离测试覆盖 npm、pnpm、Yarn、Bun、uv、pipx、Cargo；Composer/.NET 使用格式与命令夹具，本机缺少 PHP/.NET SDK，未执行真实安装。详见 [架构与验证](package-manager-architecture.md)。
