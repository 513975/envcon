# 包管理器目录迁移

更新：2026-09-13，0.5.0。十管理器复用同一复制、校验、备份、兼容链接流程，按 [能力表](package-managers.md) 提供操作；pip 仍仅迁移缓存。

## 旧功能行为

此前“收纳到根目录”只创建目录并写入包管理器配置，不会搬迁已有全局包或缓存。入口现改名为“仅设置路径”。已经改过配置的用户可通过新入口选择历史源目录补迁移。

## 操作

1. 在“包管理器 / 路径与迁移”点击对应工具的“迁移数据”。
2. 选择全局包目录或缓存/存储目录，核对原目录。可手动输入或选择历史目录。
3. 点击“预览迁移”，核对目标目录、文件数、大小和目录链接数。
4. 停止包安装、更新、开发进程和缓存清理，确认后迁移，期间保持应用打开。
5. 完成后检查原命令是否仍可运行。结果显示目标、原数据备份和 JSON 迁移记录。

## 数据与配置

- 目标为 `管理根/globals/<工具>-global` 或 `<工具>-cache`。允许空目录，不覆盖非空目标，也不合并包版本。
- 复制每个文件后逐字节校验，源内容变化或复制失败会终止。跨盘时同样采用复制。
- 校验后将源目录改名为同级 `.envcon-backup-<时间>`，再创建从原路径到新路径的 NTFS junction。包管理器配置保持原样，原有 PATH 和绝对路径脚本继续通过旧路径访问迁移后的内容。
- 备份不会自动删除，因此完成时原磁盘空间尚未释放。确认可用后可人工删除备份，保留原路径的兼容链接；不能直接把“目标数据目录”当作完整可独立迁移的便携包。
- 如果之前已将配置改到目标，选择旧源目录迁移后，目标会补齐数据；若目标已安装新包而非空，必须先人工处理冲突。
- pnpm 的 store 路径可能含版本子目录；迁移所选的实际 store 目录，旧 store 入口保留。pnpm 全局 bin 目录若独立于所选源，不会自动移动。
- Yarn Classic 可迁移全局包目录；Berry 没有 Classic 的全局安装功能，选择其实际缓存/存储目录即可。
- pip 只迁移缓存，不移动解释器、虚拟环境或 `site-packages`。Python 包/启动器与解释器绑定，不能按普通缓存搬走。
- 已安装的 Python 包可使用独立的“重装旧包”入口，从旧解释器或 site-packages 读取清单，在新虚拟环境重装；详见 [Python 包重装](python-package-reinstall.md)。
- npm/pnpm/Yarn Classic 可在“重装旧包”中选择启动器和历史目录，在新目录或已配置的空普通目录重新安装；0.4.3 的目标直接对应实际全局安装路径，详见 [全局包重装](global-package-reinstall.md)。
- npm prefix 若包含 `node.exe`，会拒绝整体搬迁，防止移动 Node 运行时。此类安装需要另行重装全局包到独立 prefix。
- Bun、uv、pipx、Cargo、Composer、.NET Tools 可选择独立工具目录迁移；包含 Bun/Rust/.NET 等运行时的目录会拒绝整体搬走。外置 bin 启动器不包含在迁移数据内，原路径兼容链接用于维持绝对路径引用。

## 限制与恢复

- 源与目标不能相同、嵌套、为系统/用户/管理根或其祖先；源和目标入口不能是链接。内部目录链接保留其引用，不遍历或复制外部目标；文件符号链接与未知重解析点会拒绝迁移。
- 迁移、路径配置和缓存清理互斥。其他应用仍可能写入原目录，因此必须先停止相关进程；此操作不是在线一致性快照。
- 复制失败保留原数据和已复制目标，并返回具体路径，不自动删除不确定的数据。重试前人工检查并移走失败副本。
- 创建旧路径链接失败时尝试把备份恢复原名；恢复失败会返回备份位置。切换前在 `globals` 写入 JSON 记录，包含源、目标、备份。
- 意外退出后先检查原路径是否为 junction。原路径缺失时可把备份改回原名；原路径为有效 junction 时先验证目标内容。不要合并或覆盖两个目录，也不要用会跟随链接的递归删除方式清理旧入口。

## 验证

Windows 临时目录夹具覆盖数据保留、内部链接、空目标、拒绝非空目标、预览变化、参数篡改、运行时目录与被占用文件。测试不操作真实用户全局包和缓存。

最初 0.3.x 验证：Rust 33 passed / 1 ignored，前端生产构建通过；`tests/migration-ui.mjs` 在 1100×720 与 900×640 下验证预览、历史目录、冲突、确认及成功报告。0.5.0 验证见 [架构文档](package-manager-architecture.md)。真实包管理器进程被占用及多卷权限组合仍需在实际使用时遵循停止进程和保留备份要求。
