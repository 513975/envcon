# Python 包重装

本功能已包含在 0.3.x 构建中。0.4.0 起入口位于“包管理器 / 路径与迁移 / pip / 重装旧包”，即使当前未检测到 pip，也可手动选择 Python。0.3.1 增加进程树超时清理、取消后的最终核对及任务状态恢复保护。

0.4.2 起，全部重装成功后提供可选的 [旧包清理](old-package-cleanup.md)。通过旧解释器卸载已验证的包，保留解释器；孤立 site-packages 不自动删除。

## 为什么不直接搬包目录

缓存是可重新生成的下载数据；已安装包则属于某个 Python 环境。Scripts 下启动器可能嵌入旧解释器路径，`.pyd` 等二进制模块依赖 Python 版本和架构。重新安装可以按目标解释器解析依赖、选择 wheel 并生成新脚本。

## 使用流程

1. 选择旧 `python.exe`，或选择残留的 `site-packages` 目录。旧解释器须可运行；目录模式用目标 Python 读取元数据，不导入旧包。读取功能需要 Python 3.8+ 的 `importlib.metadata`。
2. 选择目标 `python.exe`。目标需支持 `venv` 和 `ensurepip`；不支持的嵌入式 Python 会报告创建失败。
3. 设置尚不存在的新虚拟环境目录，父目录必须存在。不会写入已有环境或修改全局 Python。
4. 读取清单并选择要重装的包。包名和版本来自安装元数据；本地、URL、可编辑安装以及同名冲突会标出并禁选。旧 pip/setuptools/wheel 不固定到旧版本。
5. 确认后创建新 venv，以 `包名==旧版本` 逐包安装，所选版本清单同时用作依赖约束。未选中的依赖仍可能由 pip 自动安装。
6. 每个包分别记录成功/失败，最后核对版本并执行 `pip check`。用新目录下的 `Scripts/python.exe` 运行程序，或激活该 venv。不会自动修改 PATH 或 EnvCon current。

## 结果与边界

- 默认使用 pip 的默认索引（PyPI）；不继承 PIP_*、PYTHON* 和 pip 配置文件，避免旧 PIP_TARGET、prefix 或 user 配置把包装到新环境之外。系统网络代理仍可继承。私有索引/本地包需人工恢复，本轮没有新增索引选择。
- 源解释器模式包括该解释器可见包，基础 Python 额外读取用户级 site-packages。它不能还原项目源码、无元数据的手工拷贝包、系统 DLL 或非 pip 工具安装的完整依赖关系。
- 新版 Python 可能不支持旧版本包；遇到构建失败、缺少发行文件或依赖冲突会报告，不自动升级到另一版本。
- 任务可后台运行并重新打开查看。“停止后续安装”在当前命令完成后停止，不强制中断正在安装的包。应用退出会结束任务跟踪；不要在安装期间退出应用。
- 每个安装命令最多等待 10 分钟。失败和停止都会保留新环境，已成功安装的包不会回滚。重新运行需另选尚不存在的目录，或先人工处理失败环境。
- 新环境中保存 `envcon-source.json`、`envcon-requirements.txt`、`envcon-reinstall.json`，分别记录源清单、选中的固定版本和任务结果。应用重启后可直接读取报告；进程内只展示最近一次任务。
- 旧环境、旧包和其配置不修改。安装成功不等于业务代码已兼容目标 Python，仍需运行原项目验证。

## 验证

单元测试覆盖包名/版本参数校验、直接来源禁选、重复元数据和目标冲突。额外离线测试在临时目录读取旧元数据、创建真实 venv、安装本地 fixture wheel、导入模块并执行 pip check，不向用户环境安装包。

验证结果：Rust 35 passed / 2 ignored；显式运行离线 Python 集成测试 1 passed。前端构建、差异检查、重装与迁移窗口 Playwright 测试均通过。未对用户真实包执行网络重装，未验证所有发行包跨 Python 版本的兼容性。
