# 旧包清理（0.5.1）

0.5.1 增加独立入口：完成旧包扫描后，展开来源并点击删除旧包，预览可删除项、逐包选择并确认。无需先重装；清理计划仅在当前会话有效，执行前重读清单，拒绝来源变化、版本变化、越界文件及管理器自身。无解释器的孤立 Python 包目录保留并显示原因。以下“全部重装成功”条件仅适用于重装后的清理入口。

0.4.3 延续以下清理约束；npm/pnpm/Yarn 的新包验证改为直接使用所选目标全局目录，与新版重装布局一致。历史任务报告不会被当作当前会话的新清理授权。

之前的重装只在新目录安装，保留全部旧包。0.5.0 中十种管理器的重装任务全部成功后，均接入“清理已重装的旧包”；默认仍保留旧包。

## 操作

1. 重装成功后先测试新环境，配置所需的包管理器路径和 PATH。
2. 点击“清理已重装的旧包”，后端重新读取当前任务、新旧版本和实际目录。
3. 勾选待卸载包。变更版本、已不存在、新副本缺失或无法安全卸载的包会禁用并显示原因。
4. 确认新环境可用、路径已切换后执行卸载；也可点“保留旧包”退出。
5. 查看逐包结果和新目录中的 `envcon-cleanup-*.json` 报告。失败不冒充成功，重新尝试需重新预览。

## 删除范围

- 调用旧环境对应的管理器卸载指定包，不递归删除整个源目录、Python/Node 运行时或用户目录。
- npm 使用明确的旧 prefix；pnpm/Yarn 使用明确的旧 global-dir/global-folder，并先查询核对实际生效位置。Node 卸载禁用生命周期脚本。
- 包管理器可能清除所选包不再需要的依赖；其他顶层包保留。依赖旧包的旧项目可能因此不能运行。
- pnpm/Yarn 的外置旧命令入口保留，不根据当前配置推断并删除；使用新命令目录后，可人工核对残留旧入口。缓存和 PATH 不由此功能清理。
- pip 只卸载旧解释器自身的安装范围，不处理用户级包。运行时以及 pip/setuptools/wheel 保留。
- 从 site-packages 恢复的任务，必须还能找到与该目录匹配的旧解释器；孤立目录、缺少 RECORD、越界卸载记录、共享文件或重复分发包不能自动卸载。

## 复核与恢复

- 只允许当前应用会话内保留来源记录、状态为全部成功的重装任务。部分成功、已取消或失败的任务不提供自动清理；其他未选择的原包不在候选列表中。
- 来源计划保存在后端内存，前端不能任意提交删除路径。预览使用一次性标识，执行前和逐包卸载前重新检查目标与来源。
- 新旧目录重叠、重定向、管理器版本变化或源目录解析不一致时拒绝执行。
- 清理与迁移、重装、路径配置共用互斥锁。关闭弹窗不会放弃后台记录，但应保持整个应用运行；进程退出可能中断卸载。
- 卸载不进入回收站，不提供自动撤销或跨重启续清理。报告保存来源、目标与逐包结果；需要恢复时重新安装相应版本。
- 自动检查是元数据、目录和依赖校验，不替代新包实际使用测试，也不能隔离其他进程同时改写目录。

“迁移数据”产生的备份仍遵循 [目录迁移说明](package-manager-migration.md)。旧包清理用于“重装旧包”，不会删除迁移备份或兼容链接。

## 验证

0.5.0 新增 Bun、uv、pipx、Cargo 真实隔离安装及卸载夹具；Composer/.NET 使用离线元数据与命令夹具。uv 启动器位于源目录外、安装目录链接越界或 Cargo 可执行文件记录含路径穿越时拒绝清理。外置旧命令入口不推断删除。完整边界见 [架构与验证](package-manager-architecture.md)。

Rust 夹具覆盖非法包选择、来源丢失、版本变化、新副本缺失、路径重叠及 Junction 重定向。真实离线临时包测试覆盖 npm、pnpm 11、Yarn Classic 和 pip 卸载后新副本、运行时和其他顶层包保留；pip 还验证 RECORD 越界拒绝。界面测试覆盖四管理器、完成状态限制、确认、保留、过期预览和报告入口。
