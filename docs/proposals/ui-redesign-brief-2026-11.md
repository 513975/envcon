# EnvCon 前端重构项目说明

> 面向 OpenDesign 的设计与实现交接稿。日期：2026-11-03。状态：提案，待产品审核与排期；不是已批准的开发任务，也不表示现有功能已重做。

## 1. 目的与交付结果

为 EnvCon 的六个现有页面建立一致、清晰、可信赖的桌面端体验，并在保留现有业务逻辑和 Tauri 契约的前提下，逐步重建前端界面。第一目标是让用户看懂“本机发现了什么、来源和可信状态如何、操作将改变什么”，然后才是视觉焕新。

OpenDesign 交付应包含：

1. 覆盖六个页面的完整信息架构、导航和关键任务流。
2. 可交互的桌面端原型，包含正常、加载、空、错误、部分成功和危险确认状态，而不是只有静态首页。
3. 可落地的设计系统：颜色与语义状态、字体、间距、布局、图标、表格/列表、表单、弹窗、Toast、进度与空状态。
4. 与本说明匹配的前端实现方案；实现时复用当前 React/Tauri 数据接口，不伪造后端行为。
5. 一份逐页核对清单，确认现有能力、操作边界和页面跳转均有对应界面。

首轮设计不需要新增 Rust/Tauri 命令。若设计发现现有数据不足以正确表达某状态，先列为待确认的产品/接口问题，不用静态假数据掩盖。

## 2. 产品事实与不可越过的边界

### 产品定位

EnvCon 是面向 Windows 的开发环境工具下载与扫描工具。核心价值是帮助用户找到合适的 Windows 工具发行版、查看本机已发现的安装、核对版本/路径/状态，并安全地完成有限的受管操作。

现有版本切换、PATH/环境变量、包管理器、迁移与缓存能力继续保留为辅助能力。它们是需要重新组织和表达的既有功能，不代表产品要扩展成完整开发环境平台。

### 明确不属于本次承诺

- 不做项目依赖求解、项目自动配置、项目环境隔离、IDE、容器或一键启动项目。
- 不宣称安装一个工具即可得到完整开发环境；不把 C/C++、Windows SDK、MSVC、MinGW 等描述成已打通的一体化工具链。
- 不新增仓库没有的自动扫描、自动修复、自动回滚、自动升级或后台静默行为。
- 不把“扫描列表中未出现”直接翻译成“系统未安装”。
- 不把下载完成、本地计算出的哈希或 HTTP 成功当成来源可信/安装成功的证明。
- 不把受管目录删除、外部链接脱管、厂商卸载器、用户级包、共享缓存和系统配置变更合并成一个语义不清的“卸载”按钮。
- 不将 PowerShell 7 与 Windows PowerShell 5.1 混为一谈；受管目标是独立 `pwsh.exe`。不得替换 5.1、写系统级 PATH 或暗示已完成 MSI/MSIX/WinGet 集成。

### 当前阶段如实表述

仓库记录 PowerShell 7 专项的目标源码版本为 0.6.0，但应用内受管安装/切换验收仍待完成，打包与正式发布也必须分别记录。前端设计不得把“0.6.0 已发布”写成事实。

本说明依据目前源码与文档形成，仓库中的版本、测试结果、适配工具范围可能继续变化。界面应以运行时 API 返回的数据和能力为准；不得在前端写死可能过期的工具数量、版本或支持承诺。

## 3. 用户与优先任务

### 主要用户

- Windows 开发者：需要获取常用语言运行时、SDK、构建工具或命令行工具，并检查它们目前位于何处。
- 经常维护多个工具版本的用户：需要理解受管版本与当前指向，并在确认后切换。
- 需要整理本机 PATH、包管理器全局目录或缓存的用户：需要在写入前查看影响，知道何时生效。
- 使用自动化 Agent 的开发者：需要确认可从新开的终端或 Agent 进程调用的工具入口；不能把为此需要的 PATH 集成误写成 EnvCon 会替用户配置 Agent。

### 重要任务顺序

1. 打开应用后快速了解本机已管理环境、扫描发现和需要注意的问题。
2. 找到某类工具当前可安装的 Windows 版本，比较来源/渠道/验证状态，再开始下载或安装。
3. 查看环境的实际版本、路径、健康状态；必要时纳管、切换、搬移或按可核对范围移除。
4. 修改 PATH/环境变量或包管理器配置前检查确切变化与受影响对象。
5. 操作后查看实际结果、未完成项和后续需要手动处理的事项。

## 4. 信息架构与导航

保持六个一级页面，不在本轮设计中凭空增加产品模块：

| 一级入口 | 定位 | 主要内容 |
|---|---|---|
| 仪表盘 | 总览与入口 | 已管理环境、目录占用估算、已启用类别、当前链接目标、根目录/扫描相关入口 |
| 环境管理 | 本机与受管环境 | 工具类别、已管理版本、本机扫描、状态诊断、切换、纳管/搬移、导入导出、移除预览 |
| 下载中心 | 发现并获取工具 | 类别、版本、来源、校验状态、目标目录、任务和安装结果 |
| 路径管理 | 环境入口配置 | 用户 PATH、系统 PATH、环境变量、current 入口与备份恢复入口 |
| 包管理器 | 包管理器与缓存维护 | 管理器状态、更新、配置、迁移、全局包、旧包、缓存 |
| 设置 | 应用存储与恢复 | 管理根目录、下载目录、配置数据模式、备份恢复、应用更新检查 |

建议桌面左侧保留固定导航；当前实现页面首次访问后 keep-alive，没有 URL 路由。设计稿不得依赖浏览器地址栏、页面刷新深链或网页式多标签能力。

当前侧栏顺序与快捷键顺序并不一致：侧栏将“包管理器”列为第 5 项、“设置”第 6 项；实际快捷键 Ctrl+5 打开设置、Ctrl+6 打开包管理器。原型应呈现一个一致的导航顺序，并在交接说明中明确标出此差异。是否更改快捷键是实现前需由产品确认的行为决策；未确认前不得静默改掉旧键位。

## 5. 全局框架与视觉方向

### 框架

- 以 Windows 桌面窗口为主，不做网页营销站，也不照搬 IDE 的多面板复杂度。
- 桌面宽屏使用侧栏 + 页面主工作区；窄窗口侧栏应能折叠/图标化，表格改为可读卡片或分组列表，避免横向溢出。
- 页面标题区应提供标题、用途说明和适用时的主要动作；不要在每个页面重复放置大量说明段落。
- 长内容只在页面主内容区域滚动；对话框需适配较矮窗口并提供内部滚动。
- 全局任务反馈应在用户可见处持续存在。下载/安装任务可并行时，每个任务需有自己的阶段、进度、取消能力和结果；“安装器阶段不可取消”等限制只在后端确实返回/已知时显示。
- 全局通知用于短反馈；重要错误、阻塞原因和需要决策的结果必须留在当前工作流或页面中，不能只闪过 Toast。

### 视觉方向建议

采用“Windows 开发工具的可靠控制台”方向：整洁、精确、克制，但有明显品牌识别；避开模板化后台面板和默认 SaaS 卡片墙。建议浅色采用偏暖的石灰白背景、墨色文字、深松绿/青绿主操作色，辅以琥珀色作为警告与待验证信号；深色模式使用低亮度墨绿/石墨底色而非纯黑。错误红、成功绿、信息蓝各自只表示语义。

标题可使用具有辨识度但易读的无衬线字体；中文正文选择清晰的 Windows 中文字体回退栈；命令、路径、版本号、摘要等精确值采用等宽字形。若新增字体资源，需离线可用、核对许可和包体影响，并保证缺字体时布局不崩。

层级通过字重、留白、分组标题、边界与图标建立，不依赖大量阴影、发光渐变或颜色本身传达状态。轻微动画仅用于页面切换、任务阶段变化等有意义的反馈；尊重减少动态效果设置。

### 语义状态

所有状态必须同时有文字/图标和可辨别的形状或位置，不能只用颜色。视觉系统至少为以下类别定义 token 和组件：

- 正常/已识别、未发现/未扫描、处理中、已完成、部分完成。
- 注意/待验证/能力受限、阻止执行、可重试错误、不可恢复/需要人工处理。
- 受管安装、外部安装/链接、当前激活、版本不匹配或入口被遮蔽。
- 数据可信来源、校验通过、无校验资料、校验无效。

不得把后端尚未提供的状态编造成事实；无法判定时明确写“未知/未扫描/无法确认”并提供现有可用的刷新或诊断路径。

## 6. 页面功能规格

### 6.1 仪表盘

**目的：** 让用户在数秒内理解 EnvCon 管理范围，而不是把汇总数字误当作全机绝对事实。

- 首次启动时提供管理根目录设置/确认引导；说明默认位置和便携模式数据位置来自实际配置。
- 展示已管理环境数量、已管理目录占用估算、已有受管版本的类别数。环境扫描状态与按需目录大小统计是两种独立状态：扫描结果时间/刷新失败/警告单独显示；目录大小未完成时按现状显示下界（如“≥ 12 GB”），不得合并成一个“扫描中”或伪造精确总量。
- 展示 current 链接所指向的版本/路径与可打开目录操作。附简短说明：链接目标不保证已运行的终端/进程实际采用该版本。
- 提供到环境管理、下载中心、路径管理的明确入口；刷新应有加载状态和失败反馈。
- 不新增“扫描全部”按钮，除非确认当前有真实、可调用的统一扫描动作。

**状态：** 首次配置、正常有数据、空根目录、扫描快照时间/刷新中/刷新失败/警告、目录大小尚未完整（下界）、部分目录无法统计、概览读取失败、便携模式。

### 6.2 环境管理

**目的：** 看清“工具类型 → 安装实例 → 来源与健康 → 当前入口 → 可执行动作”的关系。

- 环境类别使用实际 `EnvType` 和 API 数据；目前前端类型含 18 类（包括 .NET SDK、PowerShell 7），数字不能硬编码到产品营销文案。
- 类别导航/筛选需要可搜索；实例列表优先展示工具名、版本、状态、安装路径、来源/是否受管、是否 current，并能筛选/排序。
- 提供对当前已有功能的入口：纳入扫描结果、查看/打开目录、重新识别、切换版本、PATH 只读诊断/修复预览、导出路径清单、只读导入比较、搬移预览。
- .NET 要区分 SDK 与仅 Runtime 的限制；PowerShell 7 只识别独立 `pwsh.exe`，绝不将 5.1 展示为 PS7。
- “扫描未发现”与“未安装”明确区分；区分结构不完整、版本探测失败、权限/启动问题、版本可读等已有状态。列表无法证明全机不存在该工具。
- 将删除/脱管动作从实例普通操作中视觉隔离，避免误触；在执行前展示准确路径和影响范围。

**移除预览必须可扫描：** 分为“将移除”“明确保留”“未验证/不自动处理”“阻止执行”；逐项列出目录、链接、PATH/配置等对象的具体路径/身份和原因。外部纳管默认只移除 EnvCon 链接，保留源目录。若范围不完整、有阻断或需要历史链接/PATH 逐项确认，则禁用执行并说清如何继续。支持停用并保留文件等与真实后端一致的模式，禁止笼统标作“卸载干净”。

**状态：** 首次无根目录、类别无实例、加载、未扫描、扫描中、健康/不完整/无法探测、筛选无结果、动作预览失败、动作成功/部分失败。

### 6.3 下载中心

**目的：** 帮用户选出当前适配器实际支持的 Windows x64 资产，并让“来源可信度”比版本列表更醒目。

- 先选工具类别，再展示版本/渠道。版本列表仅代表当前适配器返回的可用范围，不承诺完整历史版本档案。
- 显示正式名称/版本、发布日期（仅当 API 返回）、来源类型、官方/镜像渠道、资产格式/架构（如可得）、校验状态和不可安装原因。
- 下载源切换、刷新、搜索、离线缓存提示、目标目录名编辑只在真实支持处出现；明确镜像覆盖可能与官方列表不同。
- 将“下载中”“文件已到”“校验完成”“结构检查通过”“安装完成”“安装后版本确认”作为不同阶段呈现，不合并为一个绿色“成功”状态。
- 显示并行任务列表、真实进度/速度（有数据时）、取消入口和任务失败原因。下载、解压、调用安装器各阶段的取消限制按 API 和实际执行能力表达。
- 不可验证的资产标记“未验证”并解释原因；本地计算摘要不能冒充发布方签名/来源证明。校验无效需阻止受管安装并突出原因。
- PowerShell 7 仅列 Microsoft 官方稳定版 Windows x64 ZIP；必须取得官方 SHA-256，缺少/无效时禁用受管安装。明确使用 `pwsh.exe`，不会替换 Windows PowerShell 5.1。

**状态：** 类别加载、无可用资产、离线缓存、源失败/部分失败、列表筛选无结果、校验通过、未验证、校验无效、下载失败/取消/重试、安装中、安装后校验失败、任务成功。

### 6.4 路径管理

**目的：** 在不隐藏 Windows 用户级/系统级差异的前提下，安全编辑 PATH 和环境变量。

- 将用户 PATH 与系统 PATH 分开呈现，分别显示操作范围和权限要求；系统 PATH 保存可能需要管理员授权。
- 用户 PATH 可添加、编辑、排序、删除并保存；清楚展示 current 入口、重复/遮蔽问题（若检测结果提供）、顺序对工具解析的影响。
- 提供常见和自定义环境变量的用户级/系统级配置；建议值与实际值区分，不能静默套用推荐配置。
- 保存前提供真实变更预览；每次 PATH 修改前自动备份。设置页保留恢复入口。
- 清楚提示 PATH/环境变量的用户范围；新开的终端才读取新值，已打开终端不会自动刷新。修改系统 PATH 也不等于自动更新已运行的 Agent 进程。

**状态：** 加载/读取失败、只读查看、编辑未保存、预览无变化、准备保存、管理员授权/拒绝、保存成功/部分失败、备份不可用、恢复预览。

### 6.5 包管理器

**目的：** 让用户清楚每种管理器的可用状态、真实执行入口和管理器专属能力。

- 当前包括“已安装包”“路径与迁移”“旧包扫描”等子视图；重构可改善分组，但不得丢掉子视图已有动作。
- 展示每个管理器是否可执行、版本、路径、探测结果和安装形态（若有）。缺失、无法启动、权限不足、无法解析与正常状态不可合并。
- 自更新前显示当前版本/执行路径、精确程序和参数、能力限制、阻断原因及注意事项。单项与批量更新均先预览，完成后给出逐项结果。
- 路径/缓存配置、数据迁移、旧包重装和清理先展示变化、受影响包、目标目录冲突、阻断项；执行结果允许逐项显示成功/失败/跳过。
- 保留 Python 包重装、历史全局包、uv 旧布局恢复等既有入口；不要求将细节挤在单屏，可分区/折叠，但发现与返回结果路径要清晰。
- 缓存大小统计按需执行，允许取消或显示部分结果；清理前说明精确目录和范围。
- 不承诺所有管理器都支持自更新、指定版本、通用降级、原子回滚；按真实管理器能力显示“不可用/需手动命令/仅 latest”等差异。

**状态：** 管理器不存在、版本/路径探测失败、配置为空、读取旧包中、扫描部分失败、更新预览阻止、批量有跳过项、迁移冲突、清理确认、结果部分成功。

### 6.6 设置

**目的：** 管理 EnvCon 自身存储位置与恢复，不把应用配置和工具环境配置混在一起。

- 管理根目录、下载临时目录、配置数据目录与便携/标准模式需说明各自用途及影响。
- 配置异常时清楚区分重载、有效备份恢复、历史版本回滚；恢复/回滚需有预览与确认，先显示会切换到哪个版本/文件。
- 提供 PATH 备份恢复入口，与路径管理页相互可达。
- 应用更新仅表示检查并跳转到发布页；若不自动下载安装，界面必须如实表达。
- 当前版本显示使用构建元数据，不能在 UI 文案中手工固定为 0.6.0；本次设计产物也不等于该版本正式发布。

**状态：** 设置加载中、配置异常、无有效备份、恢复预览、恢复成功/失败、更新检查中/可用/无更新/失败。

## 7. 跨页面关键流程

以下流程必须在原型中可点击走通，至少覆盖成功路径与一个失败/阻止路径：

1. **首次使用：** 配置或确认管理根目录 → 进入空的环境页/仪表盘 → 去下载中心。
2. **获取工具：** 选工具 → 查看源、版本和校验状态 → 选目标 → 启动任务 → 观察真实阶段 → 查看安装后验证结果。
3. **让 Agent/新终端调用 PowerShell 7：** 下载官方 x64 ZIP 并通过官方 SHA-256 门禁 → 安装为受管目录 → 确认 `current\powershell\pwsh.exe` → 如用户需要再去 PATH 管理将 current 入口加入用户 PATH → 提示需新启动终端/Agent。不得自动写系统 PATH。
4. **版本切换：** 选目标实例 → 展示准确的 current 变化与 PATH 影响/诊断 → 确认 → 报告是否成功以及新旧终端生效差异。
5. **移除或脱管：** 选操作语义 → 读取预览 → 对照移除/保留/未验证/阻断分组 → 必要时逐项确认历史来源不明条目 → 执行 → 逐项反馈；未知归属内容默认不删。
6. **修改 PATH/包管理器配置：** 编辑 → 后端预览精确变化与影响 → 确认 → 写入/失败 → 读取结果/备份提示。
7. **恢复配置：** 选可用备份 → 预览来源与目标 → 确认恢复 → 展示实际结果，不将“已选择备份”当成“恢复成功”。

## 8. 交互、可访问性与窗口适配

- 鼠标、键盘焦点、Enter/Space、Esc、Tab 顺序和快捷键须有一致行为；焦点不可被颜色变化以外的状态完全隐藏。确认对话框打开时焦点进入对话框，关闭后返回触发按钮。
- 图标按钮须有可读名称/Tooltip；列表、状态和进度采用适合辅助技术的语义与标签。错误通过 `role=alert` 或等效可访问方式播报，避免持续轮询反复朗读。
- 支持系统浅色/深色偏好并保证两者对比度；不要臆造目前不存在的主题设置项。若 OpenDesign 建议增加用户手动主题开关，列为可选产品决策而非既有功能。
- 可选文本（路径、命令、日志片段、版本）应支持选择和复制；长 Windows 路径可换行/截断但需有复制或查看完整值的路径。
- 设定至少 1280×800、1024×700、800×600 三档窗口检查；不将手机视图作为主要目标，但所有核心任务在窄窗口仍须可完成。
- 动态效果不妨碍任务状态理解，尊重减少动态效果；长操作提供可见进度、取消边界和完成结果。

### 实现验收

- 读状态与写操作均有加载、错误、空状态；破坏性操作先预览、执行条件继续由 API 返回值控制。
- 不存在被伪造的下载进度、校验成功、扫描完整性、工具兼容性或卸载完成结果。
- 目标窗口尺寸无横向溢出；路径、命令、哈希可读/可复制；浅色与深色下危险、禁用、焦点状态均清楚。
- 现有项目验证脚本/UI 回归通过；未通过项明确列出，不以原型演示替代。
