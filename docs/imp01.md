## 迭代 B：持久快照与失效

- 引入 scan-cache-v1.json，按数据格式和应用版本隔离；根目录/项目选择作为查询键。缓存读取上限 8 MiB，最多保留 24 组，损坏格式忽略。
- 启动先返回历史结果，UI 展示结果时间并后台核对。后端统一合并同类并发扫描、写前/写后失效和过期结果拒绝；元数据读取在 blocking worker 中执行。
- 指纹包含有效环境（只保存哈希）、应用配置、已发现可执行路径及子二进制元数据、常见管理器配置内容。界面可见时周期复核，30 秒后完整重扫；5 秒调度一次扫描组。新发现/删除/深层项目变化不依赖父目录时间戳，最终由完整重扫覆盖。
- 后台扫描组并发 1；受管分类版本探测并发 3。启动仅发现缓存位置，不递归统计大小。清理等写操作仍重新核对真实路径，不把持久快照当删除依据。
- 手动刷新跳过完成值复用；多个同时刷新共享一个在途请求。旧项目选择不会继续预热。
- 限制：应用不在前台时暂停周期工作，重新获得焦点继续；扫描本身耗时加在复核周期之后。缓存写入失败保留内存结果并显式提示。

验证：缓存专项 3 项通过；Rust 全套 82 passed / 8 ignored；原四套 UI 与新增持久快照 UI 专项均通过。最终集成复核将在 C/D 完成后执行。
